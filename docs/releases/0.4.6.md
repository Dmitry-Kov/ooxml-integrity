# ooxml-integrity 0.4.6

Release candidate for one correction: `compare()` no longer reports a comment,
footnote, endnote or header/footer as lost when every change to it is a tracked
revision. It was found on the first source of the planned review-history
benchmark, a review record written by Word for Mac. Publication is pending the
release workflow; current consumer/demo examples remain pinned to published
0.4.5 during preparation. Python 3.9+, dependencies and the MIT license are
unchanged. The project remains research-alpha.

## Gate changes and limits

This correction removes findings and can change exit 1 to 0:

- `FID004`-`FID007` matched comment, note and header/footer texts on their
  current `w:t` text only. In the [S2 source](../../evidence/review-history-benchmark/sources/README.md)
  Word for Mac changed `1 September` to `15 September` in an endnote and
  `Draft 3` to `Draft 4` in the header, both tracked, and `compare()` reported
  `FID006` and `FID007` errors although the old text stays as `w:delText`.
- An item with no insertion, deletion or move of its own in the source now also
  matches an edited item whose text, with every revision rejected, is the
  source text. Each edited item accounts for at most one source item, so losing
  one of two identical notes is still reported. The same edit made untracked is
  reported as before.
- Items that already had pending revisions keep the exact current-text match:
  rejecting one of those revisions restores the same text while the reviewer's
  revision is lost. A new tracked edit to such an item is therefore still
  reported as a loss; this limit remains.

The public-corpus numbers are unchanged: the `mutate` edits detect 33/33
revision, 42/42 footnote and 40/40 comment losses with no careful edit flagged,
and 1,819 python-docx no-op pairs produce no finding. The committed evidence
evaluators give identical output before and after the correction.

## Compatibility

No rule code is added, removed or repurposed, and no severity changes. Messages,
`extra` fields, report fields, coverage schema 1, Doctor schema 1, SARIF 2.1.0,
CLI exits 0/1/2 and baseline v2 identities are unchanged; an obsolete baseline
entry for a finding that no longer occurs may remain unused. JSON/Doctor package
version becomes `0.4.6`. See the [compatibility policy](../compatibility.md).

## Validation and publication

[Candidate validation](../../evidence/releases/0.4.6/README.md) passed:
1147 tests with 7 documented skips, on Python 3.12 and 3.14, the 220-pair
producer corpus, 30 revision pairs and 168 stored editor output pairs, the
frozen checker replay, the four comment-story pairs, reference-deck assertions,
strict wheel/sdist metadata checks and both fresh installations, plus all 7 real
Chromium/Pyodide scenarios against the exact local candidate wheel. The
installed-package smoke compares the S2 Word review with its base and a tracked
against an untracked header edit. No new Office, adeu or model run was part of
release packaging. Local candidate and later publication hashes are separate
records.

After candidate checks pass, CI must pass on the exact merged main commit before
tagging. The Release workflow then verifies the remote pinned Action, rebuilds
and tests distributions, publishes those files to PyPI, and creates the GitHub
Release. Public PyPI installation/hash verification and consumer/demo pin updates
follow publication. See [release procedure](../releasing.md).

Use these pins **after publication**:

```sh
python -m pip install --upgrade ooxml-integrity==0.4.6
python -m ooxml_integrity --version
```

```yaml
- uses: Dmitry-Kov/ooxml-integrity@v0.4.6
  with:
    files: "out/**/*.docx"
    against: templates/master.docx
    fail-on: error
```
