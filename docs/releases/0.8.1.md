# ooxml-integrity 0.8.1

Published 2026-10-12T16:21:10Z on [PyPI](https://pypi.org/project/ooxml-integrity/0.8.1/)
and as a [GitHub Release](https://github.com/Dmitry-Kov/ooxml-integrity/releases/tag/v0.8.1). A stabilisation release from
an external review of 0.8.0: security fixes to `anonymize`, `fix` refusing
repairs whose result is not unique, text rules reading hyphen, symbol and tab
elements, and globs matching segment by segment. Python 3.9+, dependencies and
the MIT license are unchanged. The project remains research-alpha.

## Anonymized copies: what to check

Copies made by 0.5.0 to 0.8.0 may hold values of the original that their leak
scan did not report: attribute values in a firm's own namespace on Word
elements, string literals in data binding paths (whose bindings also select
nothing), prefixes bound to a firm's namespace, and attribute values in parts
that are not well-formed XML. Those versions could also write over an input
whose path, or a link to it, was one of the output names.
[SECURITY.md](../../SECURITY.md#copies-made-by-050-to-080) says how to check a
copy before sharing it; making it again with 0.8.1 replaces the first three and
reports the fourth.

## `anonymize`

- An output that is an input, or a symbolic or hard link to one, or the pair's
  other source, is refused before anything is written (exit 2, also with
  `--force`). The originals' findings are read before any copy is published.
- Attribute values in a custom namespace are replaced in every part.
- A data binding's string literals are mapped like the values they compare
  with, so the binding still selects its data; paths that cannot be mapped
  safely are refused. A new check evaluates every binding in the original and
  the copy and fails the run (exit 1) when the node counts differ; the JSON
  report lists them as `bindings`.
- Prefixes of custom namespaces become `ns0`, `ns1`, … in every place they are
  used; a renamed part must parse to the same tree.
- The leak scan reads all of these, and in parts that are not well-formed XML
  it reads attribute values, where it read their names since 0.5.0.

The [measurement](../../evidence/anonymize/README.md) was rerun: every
repository pair is unchanged; of the public corpora 1,846 documents are
anonymized (2 refused, a `name()` binding), every finding is reproduced, 77
documents with 317 data bindings still select the same data, and 11 leak
reports appear in LibreOffice test files whose parts paste several XML
documents together — values the old scan did not see.

## `fix`

- anchor-replies is refused when anything but comment marks lies between the
  end of the parent's range and where the reply's range would end; the
  re-check now also requires the reply's range to cover what its parent's
  covers. 0.8.0 could give a reply a wider range and pass its re-check.
- content-type is refused when the part's root element is not the one its
  relationship type's parts have; 0.8.0 could declare a styles part as
  settings because its relationship said so.
- Without `--force`, where hard links are not supported, the output is created
  exclusively and never replaces a file that appeared meanwhile.

No repository file's `fix` result changes ([record](../../evidence/fix-repairs/README.md)).

## Text rules and globs

- `FID004`–`FID007`, `FID010`, `FID013` and `FID014` read a non-breaking
  hyphen as `-`, a soft hyphen as nothing, a symbol as its character and an
  absolute position tab as a tab, and tabs and breaks as whitespace. 0.8.0's
  `FID014` missed "non‑compete" becoming "noncompete"; `FID013` missed a
  replacement whose words were separated by tabs.
- `ignore` and `expect` path globs match segment by segment: 0.8.0's
  `out/**/accepted/*.docx` also covered `out/a/accepted/nested/file.docx`.
- The `FID014` expectation recipe names `before`, `after` and
  `change = "changed"`, since `after` alone also accepted an edit of another
  paragraph that produced that text
  ([configuration](../configuration.md#changes-the-edit-was-asked-to-make)).

No recorded evidence changes from these: none of the repository's DOCX holds
the elements, and the corpus, revision-text, comment-story, recheck and
benchmark expectation gates report what 0.8.0 reported.

## Compatibility

- A glob that matched more in 0.8.0 covers fewer files: a finding an
  over-broad `ignore` hid can appear and fail the run, and an `expect` entry no
  longer applies outside its pattern.
- A finding of `FID004`–`FID007`, `FID010`, `FID013` or `FID014` whose text
  holds one of the newly read elements gets another baseline v2 identity;
  review it and regenerate the baseline.
- `anonymize` and `fix` refuse more inputs (exit 2 and 1 as described above);
  `anonymize --json` gains `bindings`.
- Other rule codes, severities, report fields, coverage schema 1, Doctor
  schema 1, SARIF 2.1.0 and CLI exits are those of 0.8.0. JSON/Doctor package
  version becomes `0.8.1`. See the [compatibility policy](../compatibility.md).
