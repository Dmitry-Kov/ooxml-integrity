# ooxml-integrity 0.11.0

Published 2026-11-20T07:24:41Z on [PyPI](https://pypi.org/project/ooxml-integrity/0.11.0/)
and as a [GitHub Release](https://github.com/Dmitry-Kov/ooxml-integrity/releases/tag/v0.11.0).
A report no longer replaces a file the run reads or an
Office file it was not asked to write; a Word text box is read from the copy
Word shows; a comparison that could not run can no longer be baselined; and
`FTN002` reports an ordinary footnote numbered 0. A document, a comparison or a
CI job that passed can now fail, hence the minor version. Python 3.9+,
dependencies and the MIT license are unchanged. The project remains
research-alpha.

## Reports never replace what a run reads

Writing a report could destroy a file. `check --sarif` and `--write-baseline`
wrote over an input document when a shell glob put its name after the option,
over the baseline or the config the run had just read, and over any existing
`.docx` or `.pptx`. The Action's `json-report` did the same, with no check at
all. On 0.10.0, `check base.docx --baseline accepted.json --sarif
accepted.json` exits 0 and leaves SARIF where the baseline was; the next run
with that baseline exits 2.

- **One rule for the CLI and the Action.** A report path is refused, with exit
  2 and nothing written, when it is a checked document, the `--against`
  source, the baseline or the loaded config, by any name or symbolic or hard
  link; an existing `.docx`, `.pptx`, `.potx` or `.ppsx`, also through a
  symbolic link; or an existing file with more than one hard link, since the
  other name may be a document outside the run.
- **Refreshing a baseline still works.** `--write-baseline` may use the path
  of `--baseline`, unless that baseline has another hard link.
- **The Action checks both reports before publishing either.** SARIF and JSON
  are written to a temporary directory first; one path for both is refused.
  The guard comes from the Action's own ref, also with a `version` override.

## A Word text box is read from the copy Word shows

Word writes a text box twice inside `mc:AlternateContent`: a `mc:Choice` for
current readers and a `mc:Fallback` for older ones. The first branch is what
Word shows; 0.10.0 already read it for `CMT007`, bookmarks and fields. 0.11.0
reads it everywhere a copy could hide a defect or report a false one.

- **Comment anchors (`CMT001`–`CMT005`).** A range in the primary copy whose
  only reference is in the fallback is `CMT003`, and `CMT005` if no other
  story refers to the comment. 0.10.0 passed such a file. A reference to an
  unknown comment id only in the fallback is no longer `CMT004`.
- **The requested edit (`FID014`, `EXP001`).** A change made only to the
  fallback copy no longer satisfies an expectation; it fails with `EXP001`.
- **The comparison with a source.** `compare()` counts and reads the primary
  and the fallback copies separately. A loss in the primary copy keeps its
  severity: moving the only comment reference into the fallback is `FID001`
  ERROR, where 0.10.0 saw an unchanged total. A loss confined to the fallback
  is a WARN with "Fallback copy:" in its message and `extra.branch:
  "fallback"`, so an edit that drops only the copy older readers use passes the
  default gate. 0.10.0 counted both copies together and reported such an edit
  as an `FID001` ERROR, and as `FID003` when the copy held enough text.
- **`fix` and coverage follow the same rule.** `anchor-replies` skips a reply
  whose thread has a marker in a text box, with the reason, and goes on with
  other repairs; a copy of a comment definition inside `mc:AlternateContent`
  no longer blocks a repair. Coverage counts the comment references `check`
  read.

None of the 1,589 documents and decks under `corpus/` and `evidence/` contains
`mc:AlternateContent`, so these changes were verified on synthetic text boxes
and synthetic variants of captured documents, not in Word. On the [public corpora](../real-world-corpora.md), 294 of 1,887 Word files
have `mc:AlternateContent`, and `check()` gives every one of the 1,887 the
same findings as 0.10.0 ([record](../../evidence/releases/0.11.0/public-corpora.json)).

## Failed comparisons stay visible

`FID000` means the requested `--against` comparison did not run. A baseline
no longer records it: `--write-baseline` leaves it out with a warning, and an
entry an older v2 baseline holds for it is ignored. A `.pptx`, `.potx` or
`.ppsx` deck checked with `--against` always gets `FID000`, since decks are not
compared; such a run now fails until `--against` is left out for decks or a
config `ignore` with a reason accepts it.

## Other changes

- **`FTN002` for footnote 0.** An unreferenced footnote was skipped when its
  id was `-1` or `0`. Separators are known by `w:type`, and an ordinary
  footnote numbered 0 that lost its reference is now `FTN002` ERROR. Typed
  separators, including LibreOffice's `0` and `1`, still pass. Verified on
  synthetic documents.
- **No false `PPT006` on Two Content slides.** When both columns inherit their
  geometry from the layout, each now takes the placeholder with its own `idx`;
  both were placed in the left rectangle. Verified on synthetic slides.
- **The Action uses the project's threshold.** With `fail-on` left empty, the
  CLI applies the config's `fail_on`, else `error`; the Action passed `error`
  regardless. The step exits with the higher code of its two passes, so a
  report that could not be written fails it, and the `sarif`, `errors` and
  `warnings` outputs are empty after a usage error.
- **A pre-commit hook.** `.pre-commit-hooks.yaml` runs `ooxml-integrity check`
  on the `.docx` and `.pptx` files of a commit, without a source
  ([configuration](../configuration.md#before-a-commit)). 0.11.0 is the first
  tag that has it.
- **Type annotations.** CI runs mypy over the package, which ships `py.typed`.
  No check, message or exit code changed.

## Compatibility

A pinned 0.10.0 job can change its result in these cases:

- **A document that passed can exit 1** when a text box has a comment range
  whose reference is only in its fallback copy (`CMT003`, `CMT005` ERROR), or
  an unreferenced ordinary footnote numbered 0 (`FTN002` ERROR).
- **A comparison that passed can exit 1** when the edit moved a construct out
  of a text box's primary copy (`FID001` ERROR), changed only the fallback copy
  of a paragraph an expectation requires (`EXP001`), or when `FID000` was
  accepted by a baseline, which no longer applies. A deck with `--against`
  fails on `FID000`.
- **A run that wrote a report can exit 2** when the path is an input, the
  baseline, the config, an existing Office file or a file with another hard
  link. Give each report its own new path.
- **A comparison that failed can pass**: a loss only in a text box's fallback
  copy is a WARN, and a `--fail-on warn` job still fails on it. A deck whose
  only error was the Two Content overlap passes; remove an expectation that
  required that `PPT006`.
- **The Action fails on warnings or info** when the project's config sets
  `fail_on` to `warn` or `info` and the workflow leaves `fail-on` empty. Set
  `fail-on: error` to keep the 0.10.0 threshold.
- **Baselines.** v2 files are read as before; no migration is needed. An
  `FID000` entry is ignored. A fallback-only loss has its own `where`
  (`…/mc:AlternateContent/fallback`), so a baseline entry that accepted a
  loss counted across both copies may no longer match; review it and run
  `--write-baseline` again. `FID014` findings in documents with text boxes can
  name other paragraphs.
- Rule codes, report fields, coverage schema 1, Doctor schema 1, SARIF 2.1.0
  and baseline v2 are those of 0.10.0. A finding about a fallback copy carries
  the optional `extra.branch`. JSON/Doctor package version becomes `0.11.0`.
  See the [compatibility policy](../compatibility.md).

3207 tests with 7 documented skips on Python 3.12, the suite run from the
unpacked sdist (3105 passed, 109 skipped: the 74 new skips are agent hook tests
that read a file the sdist does not ship), `ruff` and `mypy`, the 220-pair
producer corpus, 30 revision pairs and 168 stored editor output pairs, the
frozen checker replay, the four comment-story pairs, reference-deck
assertions, a rerun of the anonymize measurement with the same result, strict
wheel/sdist metadata checks and both fresh installations, plus all 7 real
Chromium/Pyodide scenarios against the exact local candidate wheel. Python
3.14 was not run locally: the preparing machine has no 3.14 interpreter, and
the pull request's CI matrix covers 3.9 to 3.14. The installed-package smoke
adds the 0.11.0 controls: a text box whose comment reference is only in its
fallback copy (`CMT003`, `CMT005`), that reference moved there against a source
(`FID001` ERROR) and a dropped fallback copy (warnings only), an unreferenced
ordinary footnote 0 (`FTN002`), reports refused over the baseline, an
unrelated `.docx` and a hard link, and `FID000` left out of a baseline. On
0.10.0 the same inputs pass, overwrite the files, and fail the dropped
fallback copy with `FID001` and `FID003` ERROR.

A new comparison checked 0.10.0 from PyPI and this candidate on 2,497 public
files: no Word file changes its findings; five decks do, all through the
`PPT006` correction. Sixteen findings are gone and one is new, a `PPT001`
ERROR where a placeholder now takes its own 15pt layout box; whether
PowerPoint shows that overflow was not checked. No new Office, agent or model
run was part of release packaging. Local candidate and later publication
hashes are separate records.
