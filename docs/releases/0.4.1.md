# ooxml-integrity 0.4.1

Version 0.4.1 fixes missed DOCX style references, bounds ZIP metadata before
the full index is allocated, and corrects PPTX style inheritance and coverage.
Python 3.9+ and the MIT license are unchanged. The project remains research-alpha;
this patch does not establish broader OOXML or Office rendering coverage.

The source checkout can precede publication. Once this version is available on
PyPI and its GitHub tag exists, install or pin it explicitly:

```bash
python -m pip install --upgrade ooxml-integrity==0.4.1
python -m ooxml_integrity --version
```

```yaml
- uses: Dmitry-Kov/ooxml-integrity@v0.4.1
  with:
    files: "out/**/*.docx"
    against: templates/master.docx
    fail-on: error
```

## Changes that can affect a gate

- `STY001` now reports references even when `word/styles.xml` is absent.
  Undefined paragraph/table styles remain ERROR; character styles now use WARN
  instead of the ERROR in 0.4.0. Character-only findings pass the default
  `--fail-on error`; select `--fail-on warn` if these must fail your gate.
  Missing styles without references remain clean. Unreadable styles XML emits
  `XML001` with skipped style coverage, without duplicate undefined references.
- The ZIP preflight counts actual directory records before `ZipFile` allocates
  its index, including when trailer counts are forged. The new
  `archive.max-directory-bytes` budget defaults to 16 MiB and can emit `PKG007`.
  Malformed or unsupported layouts are rejected as `PKG002`; archives accepted
  by a general ZIP reader are not necessarily within this
  [bounded OOXML profile](../archive-limits.md#supported-zip-layout).
- PPTX bold and italic inherit independently of resolved size and family.
  Explicit false still overrides inherited true. Correct font selection can
  add or remove overflow findings; codes and severity thresholds are unchanged.
  See [run-property scope and regressions](../pptx-run-properties.md).
- Grow-to-fit text is explicitly reported as
  `pptx.autofit-grow-shape: skipped` and excluded from the overflow coverage
  count. Stored-rectangle geometry checks still run. This coverage change does
  not add an overflow verdict for renderer-dependent `spAutoFit` behaviour.

## Compatibility

Baseline v2 and its finding identities are unchanged; no baseline migration is
required from 0.4.0. Review newly detected references and changed PPTX findings
before accepting them into a baseline. Baseline v1 is still rejected with exit
code 2; the [0.4.0 migration instructions](0.4.0.md#breaking-change-baseline-v2)
continue to apply when upgrading from older versions.

CLI exit codes remain 0 / 1 / 2 for a passing threshold, findings and usage or
configuration errors. JSON's package `version` becomes `0.4.1`; SARIF stays
2.1.0, and coverage/Doctor stay at `schema_version: 1`. Consumers should accept
the additive coverage identifier and revised counts. Existing config keys and
the first five positional `ArchiveLimits` arguments retain their meaning; the
directory budget is an additional final argument. The Action's default install
continues to use the selected ref, with explicit source/version overrides.

## Verification and demo

The [distribution workflow](../../.github/workflows/distributions.yml) builds a
wheel from the sdist, checks metadata, installs each into a fresh environment,
and exercises both entry points, exit codes, JSON/coverage, SARIF, config and
baseline v2. The exact wheel also runs through the real Chromium/Pyodide suite.
Artifacts include checksums and browser receipts; publication reuses this
workflow and uploads only the files that passed it. Source CI retains the
Python/OS matrix, local Action checks, reproducible fixtures and the DOCX
evaluator (50 sources / 220 pairs). A release additionally tests its public
Action tag before publishing to PyPI.

The browser demo pins a published package independently. Its footer identifies
the installed version; the pin changes in a separate PR after PyPI publication
and passing public-package browser checks. The [validation record](../../demo/VALIDATION.md)
distinguishes released-package checks from local candidate previews. Browser
execution does not add Office rendering evidence. See the
[release procedure](../releasing.md) and [support matrix](../support-matrix.md).
