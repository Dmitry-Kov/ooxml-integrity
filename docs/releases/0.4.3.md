# ooxml-integrity 0.4.3

Release candidate for the paragraph revision ID correction. Publication is
pending the release workflow; current consumer/demo examples remain pinned to
published 0.4.2 during preparation. Python 3.9+, dependencies and the MIT license
are unchanged. The project remains research-alpha.

## Gate changes and limits

`REV001` no longer rejects a verified plain whole-paragraph insertion/deletion
solely because its paragraph mark and content share an ID. The exception requires
exactly two same-kind occurrences in one direct body paragraph, plain tracked
text, matching nonempty author/date and matching optional `w16du:dateUtc`.
Unrelated duplicates, third occurrences, mixed/nested/non-text structures,
moves, table paragraphs and unverified metadata retain the conservative ERROR
path. [Exact scope and native/SDK evidence](../paragraph-revision-ids.md).

An affected document can change from exit 1 to 0. This is a scoped false-positive
correction, not full OOXML conformance, revision identity or layout validation.
Word Mac 16.113 completed the 16 shared/unique insertion/deletion review controls
and selected Accept/Reject on a separate full-size replay, with save/reopen.
Windows native behavior was not tested. SDK 3.0.1 validation applies to the
synthetic controls; the full replay document was not SDK-validated.

The `REV001` message no longer predicts Word's unreadable-content warning from
an ID count alone. `FID002` now states only that a construct count increased;
it does not equate editing correctness with ID uniqueness. Historical findings
remain unchanged except the two declared message suffixes in the
[current evidence gate](../../evidence/docx-paragraph-revision-ids/PROTOCOL.md).

## Compatibility

No rule code, retained severity, report field, coverage count or schema changes.
Coverage/Doctor schema remains 1, SARIF 2.1.0, CLI exits 0/1/2, and baseline v2
identities remain compatible. Messages are excluded from baseline fingerprints;
no baseline regeneration is required. Entries for newly exempted pairs may become
unused. JSON/Doctor package version becomes `0.4.3`. FID009/FID010 scope and known
identity/presence gaps are unchanged.

## Validation and publication

[Candidate validation](../../evidence/releases/0.4.3/README.md) passed:
1046 tests with 7 documented skips, the 220-pair producer corpus, 30 revision
pairs and 168 stored editor output pairs, reference-deck assertions, strict
wheel/sdist metadata checks and both fresh installations, plus all 7 real
Chromium/Pyodide scenarios against the exact local candidate wheel.
The installed-package smoke checks insertion/deletion mark/content pairs and
their third-occurrence errors. No new Office, adeu or model run was part of release
packaging. Local candidate and later publication hashes are separate records.

After candidate checks pass, CI must pass on the exact merged main commit before
tagging. The Release workflow then verifies the remote pinned Action, rebuilds
and tests distributions, publishes those files to PyPI, and creates the GitHub
Release. Public PyPI installation/hash verification and consumer/demo pin updates
follow publication. See [release procedure](../releasing.md).

Use these pins **after publication**:

```sh
python -m pip install --upgrade ooxml-integrity==0.4.3
python -m ooxml_integrity --version
```

```yaml
- uses: Dmitry-Kov/ooxml-integrity@v0.4.3

    files: "out/**/*.docx"
    against: templates/master.docx
    fail-on: error
```
