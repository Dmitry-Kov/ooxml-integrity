# ooxml-integrity 0.4.5

Published 2026-09-28T19:13:23Z on [PyPI](https://pypi.org/project/ooxml-integrity/0.4.5/)
and as a [GitHub Release](https://github.com/Dmitry-Kov/ooxml-integrity/releases/tag/v0.4.5). This patch lowers `STY002`
for undefined `w:next`/`w:link`, names the parser limit in `XML001`, and stops
`FID003` from counting text kept as new tracked deletions as lost; CI now also
tests Python 3.14. Python 3.9+, dependencies and the MIT license are unchanged.
The project remains research-alpha.

## Gate changes and limits

These corrections lower or remove findings and can change exit 1 to 0:

- `STY002` is INFO for an undefined `w:next` or `w:link` style. ISO/IEC
  29500-1 ignores both (17.7.4.10, 17.7.4.6): a new paragraph keeps its style
  and the style is simply not paired, so the text keeps its formatting. An
  undefined `w:basedOn` stays a WARN, because the style then inherits no
  formatting (17.7.4.3). On the [public corpora](../real-world-corpora.md), 73 of
  the 79 `STY002` warnings become INFO. The default error threshold is
  unaffected; gates at `--fail-on warn` can change exit 1 to 0.
- `FID003` no longer counts text kept as a new tracked deletion as lost. In
  adeu's `01_basic_text_modification` scenario
  ([adeu #140](https://github.com/dealfluence/adeu/pull/140#issuecomment-5849013445))
  a tracked replacement shortened a 28-character document to 26 visible
  characters and was reported as 7% of content lost. The edit's new `w:delText`
  now counts toward the edited length; deletions already pending in the source
  do not, so they cannot hide an untracked loss. Untracked losses are reported
  as before. On adeu 3.0.6's six written scenario outputs, the comparison now
  reports only the revision-count changes that the two accept/reject scenarios
  request (`FID001`).

Messages only:

- `XML001` names the safe parser's limit when a part is nested deeper than 256
  elements, instead of calling it not well-formed, and `PKG006` says that a main
  part which could not be parsed was not checked, instead of calling it missing.
  POI's `deep-table-cell.docx` gets both. The parser limit itself stays, and
  such a part is still not checked.

The public-corpus numbers are otherwise unchanged: the `mutate` edits detect
33/33 revision, 42/42 footnote and 40/40 comment losses with no careful edit
flagged, and 1,819 python-docx no-op pairs produce no finding. The agent-run
summary in [research](../research.md) was corrected: five of the six careful
runs tracked their edits.

## Compatibility

No rule code is added, removed or repurposed. `STY002` for `w:next`/`w:link`
changes from WARN to INFO; other severities are unchanged. `FID003` keeps its
`before`/`after` details; when tracked deletions are counted, its message says
so and `extra` adds `tracked_deleted`. Report fields, coverage schema 1, Doctor
schema 1, SARIF 2.1.0, CLI exits 0/1/2 and baseline v2 identities are
unchanged; messages are excluded from baseline fingerprints. JSON/Doctor package
version becomes `0.4.5`. CI adds Python 3.14 on Linux and the classifiers list
it. See the [compatibility policy](../compatibility.md).
