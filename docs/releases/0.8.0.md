# ooxml-integrity 0.8.0

Published 2026-10-11T17:04:18Z on [PyPI](https://pypi.org/project/ooxml-integrity/0.8.0/)
and as a [GitHub Release](https://github.com/Dmitry-Kov/ooxml-integrity/releases/tag/v0.8.0). A new INFO finding,
`FID014`, lists the paragraphs an edit changed, so a caller can require the text
the edit was asked to produce. Python 3.9+, dependencies and the MIT license
are unchanged. The project remains research-alpha.

## The text an edit was asked to produce: `FID014`

The loss rules say what an edit removed, not whether it made the requested
change. In the review-history benchmark docx-cli, asked to replace "disputed
amount" inside another reviewer's pending insertion without tracking, rewrote
another span of it and lost nothing any rule counts; nothing reported it.

- `FID014` (INFO, `compare()`) reports each paragraph whose text the edit
  changed, added or removed, with its text before and after, read with tracked
  changes accepted (`before`, `after`) and rejected (`before_original`,
  `after_original`). Whitespace is normalised and empty paragraphs are left
  out; a header or footer story is read as the distinct texts its section slots
  show.
- An expectation of `FID014` with the paragraph the edit was asked to produce
  fails with `EXP001` when the paragraph reads otherwise
  ([configuration](../configuration.md#changes-the-edit-was-asked-to-make)):

  ```toml
  [[expect]]
  code = "FID014"
  reason = "the task replaces 'disputed amount' with 'disputed sum'"
  match = { story = "document", after = "Fees are payable within forty-five days of receipt of a valid invoice. The Client may withhold disputed sum." }
  ```

Expecting each replacement's declared text, the benchmark's expectations
analysis catches 69 of 69 damaged outputs (67 without it), with flagged correct
outputs still 12 of 537, and flags 26 of 30 incomplete outputs, among them
twelve K4 edits that python-docx and Office-Word-MCP-Server reported as done
without making
([fourth reading](../../evidence/review-history-benchmark/expectations/README.md#fourth-reading-the-text-the-edit-was-asked-to-produce)).

## Compatibility

- `FID014` is a new INFO finding. It never fails the default gate; a
  `--fail-on info` gate that compares an edit now fails on the paragraphs it
  changed, as it already did on `FID002` and `FID012`. Reports, SARIF and the
  MCP verdict's info counts grow by the paragraphs an edit changed. Its
  baseline v2 identity hashes the story, the change and both texts in both
  views; no document text enters a baseline.
- Other rule codes, severities, messages, report fields, coverage schema 1,
  Doctor schema 1, SARIF 2.1.0, CLI exits 0/1/2 and baseline v2 identities are
  those of 0.7.0. JSON/Doctor package version becomes `0.8.0`. See the
  [compatibility policy](../compatibility.md).
