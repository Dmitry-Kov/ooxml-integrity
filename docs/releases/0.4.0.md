# ooxml-integrity 0.4.0

Released 2026-09-06. Version 0.4.0 fixes cases where document comparison could
miss a new loss, adds package-reading checks and coverage reports, and corrects
PPTX measurements found during renderer testing. Requires Python 3.9+ and is
released under MIT. The project remains research-alpha, with incomplete OOXML
coverage and layout estimates that can differ from an Office renderer.

```bash
python -m pip install --upgrade ooxml-integrity==0.4.0
python -m ooxml_integrity --version
```

For GitHub Actions, pin `Dmitry-Kov/ooxml-integrity@v0.4.0`.

## Breaking change: baseline v2

Version 1 baseline fingerprints could let an accepted fidelity loss hide a
different new loss with the same rule code. Version 0.4.0 rejects v1 baselines
with exit code 2 and instructions to regenerate them. Changing the JSON version
number by hand will not migrate a baseline: the finding identities have changed.

1. Preserve the previous baseline in version control or a backup.
2. Run the same files and source comparison without `--baseline` and review
   the findings. Repair anything that should not be accepted.
3. Write a fresh baseline with the same paths, source, and working directory.
4. Review and commit the new baseline, then re-enable the baseline gate.

For example (replace paths with those used by your existing check):

```bash
ooxml-integrity check "out/**/*.docx" --against templates/master.docx --no-config
ooxml-integrity check "out/**/*.docx" --against templates/master.docx \
  --write-baseline .ooxml-integrity-baseline.json
ooxml-integrity check "out/**/*.docx" --against templates/master.docx \
  --baseline .ooxml-integrity-baseline.json
```

Writing a baseline records the current findings as accepted and leaves the
documents as they are. The new supported fidelity identities omit plaintext
document bodies. Also review any baseline generated from the old, incorrect
PPTX slide positions or theme-font measurements.

## What's included

- DOCX header/footer fidelity: `FID007` detects missing or changed effective
  stories; `FID008` detects tracked constructs lost from those stories.
- Safe XML parsing; package-wide DOCX relationship checks; configurable ZIP
  budgets (`PKG007`) and unsafe/duplicate member-name rejection (`PKG008`).
- `check --coverage`, `--coverage-details`, and `doctor` report what was inspected,
  estimated, skipped or recognised as unsupported. An unreadable source or
  unsupported PPTX `--against` comparison now produces an explicit failure.
- PPTX fixes for basic-Latin long-word wrapping, static TTC/OTC face indices,
  main presentation slide order, and owning-master Latin theme fonts. Native
  PowerPoint evidence covers 29 added slides across these four changes.
- The composite Action installs code from the selected Action ref by default,
  not the latest PyPI version. Explicit `version`/`source` overrides remain.
- Published synthetic DOCX evidence: 50 sources from five producers, 220 labelled
  pairs, including 120 clean controls. Error-level precision and recall are
  100% on this labelled corpus. Production files outside the corpus remain
  unmeasured.

## Compatibility and known limits

- CLI exit codes remain `0` (clean at the selected threshold), `1` (findings),
  and `2` (usage/configuration error). JSON's top-level `version` is the package
  version, now `0.4.0`, not a new schema identifier. Existing JSON fields and
  SARIF 2.1.0 are retained; coverage/doctor use `schema_version: 1`.
- Grouped objects, rotated bounds, table layout, SmartArt, chart text, complex
  shaping and complete PPTX OPC validation remain limited or unsupported.
  Theme font-scheme overrides fail closed rather than borrowing another font.
- Coverage continues to report font substitutions and unavailable fonts.
  Measurements still depend on the fonts available on the host.
- Existing environment-specific font-test skips and upstream Node-runtime
  deprecation annotations in the legacy CI/Action are not product test failures.
  External production evidence and independent review remain open beta gates.
