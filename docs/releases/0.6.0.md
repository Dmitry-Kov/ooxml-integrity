# ooxml-integrity 0.6.0

Release candidate. `ooxml-integrity mcp` lets an agent check a document it
edited before it returns the file. The checks are those of 0.5.3. Python
3.9+, dependencies and the MIT license are unchanged. The project remains
research-alpha.

## Checking from an agent: `ooxml-integrity mcp`

A local [Model Context Protocol](https://modelcontextprotocol.io/) server on
stdin and stdout, started by the agent's client:

```bash
claude mcp add ooxml-integrity -- ooxml-integrity mcp
```

- Two tools. `check(path)` is `check PATH --json --coverage`;
  `compare(source, edited)` adds `--against SOURCE` and takes the changes the
  edit was asked to make as `expect` entries, in the format of `[[expect]]`.
- A result carries the CLI's JSON report, the exit code `check` would return
  and a one-line verdict. The verdict says `clean` only when there are no
  findings and coverage has no estimated, skipped or unsupported item, as
  `check --coverage` does; a `.docx` checked without its original is never
  called clean. Findings are not tool errors.
- Only regular files on the machine are read. URLs and network paths are
  refused before any filesystem access; the server opens no socket and never
  writes or deletes anything.
- The config is the CLI's, found from the server's working directory or set
  with `--config`, `--no-config` and `--fail-on` when it starts. A call can
  declare an expected change but cannot turn a rule off or lower the threshold.
- No new dependency: the protocol subset (initialize, ping, tools/list,
  tools/call; protocol versions 2025-11-25, 2025-06-18, 2025-03-26 and
  2024-11-05) is implemented in the package.

The [MCP guide](../mcp.md) has the configuration for Claude Code, Codex and
OpenCode and the result format.

## Compatibility

No finding changes: rule codes, severities, messages, report fields, coverage
schema 1, Doctor schema 1, SARIF 2.1.0, CLI exits 0/1/2, baseline v2
identities and `anonymize` output are those of 0.5.3. The MCP server is a new
interface without a contract of its own yet: its tool names, arguments and the
result around the report can change until a release documents them; the report
inside a result keeps the CLI's JSON contract. JSON/Doctor package version
becomes `0.6.0`. See the [compatibility policy](../compatibility.md#machine-readable-formats).

## Validation and publication

[Candidate validation](../../evidence/releases/0.6.0/README.md) passed:
2255 tests with 7 documented skips, on Python 3.12 and 3.14, the
suite run from the unpacked sdist (2228 passed, 34 skipped), the 220-pair
producer corpus, 30 revision pairs and 168 stored editor output pairs, the
frozen checker replay, the four comment-story pairs, reference-deck assertions,
a rerun of the anonymize measurement with the same result, strict wheel/sdist
metadata checks and both fresh installations, plus all 7 real Chromium/Pyodide
scenarios against the exact local candidate wheel. The installed-package smoke
adds the 0.6.0 control: `ooxml-integrity mcp` answers over stdio with the CLI's
report and refuses a URL. No new Office, agent or model run was part of
release packaging. Local candidate and later
publication hashes are separate records.

After candidate checks pass, CI must pass on the exact merged main commit before
tagging. The Release workflow then verifies the remote pinned Action, rebuilds
and tests distributions, publishes those files to PyPI, and creates the GitHub
Release. Public PyPI installation/hash verification and consumer/demo pin updates
follow publication. See [release procedure](../releasing.md).

Use these pins **after publication**:

```sh
python -m pip install --upgrade ooxml-integrity==0.6.0
python -m ooxml_integrity --version
```

```yaml
- uses: Dmitry-Kov/ooxml-integrity@v0.6.0
  with:
    files: "out/**/*.docx"
    against: templates/master.docx
    fail-on: error
```
