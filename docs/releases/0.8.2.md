# ooxml-integrity 0.8.2

Published 2026-10-24T06:18:40Z on [PyPI](https://pypi.org/project/ooxml-integrity/0.8.2/)
and as a [GitHub Release](https://github.com/Dmitry-Kov/ooxml-integrity/releases/tag/v0.8.2). A security release of
`anonymize`, which now replaces a firm's names in custom XML markup, smart tags
and their settings, and the values a part that is not well-formed XML kept;
comment and note texts read a paragraph boundary as a space, so reflowing a
comment is no longer a lost comment. Python 3.9+, dependencies and the MIT
license are unchanged. The project remains research-alpha.

## Anonymized copies: what to check

Copies made by 0.5.0 to 0.8.1 may hold names and values of the original that
their leak scan did not report: the element and attribute names and the
placeholder text of custom XML markup (`<w:customXml w:element="ClientName">`)
and of smart tags in a firm's namespace; in the settings, smart tag types,
the schema library's schema and manifest locations (often file paths with a
user or server name) and the transform a document is saved through; and in a
part that is not well-formed XML, hyperlink addresses on VML shapes, external
relationship targets, custom style names, numbering formats, form field names
and data binding paths.
[SECURITY.md](../../SECURITY.md#copies-made-by-050-to-081) says how to check a
copy before sharing it; making it again with 0.8.2 replaces them.

## `anonymize`

- **Custom XML markup and smart tags.** A firm's element and attribute names
  are renamed as the same names are in its custom XML data, so the markup
  still names the data's elements; an element without a namespace is the
  firm's too. Placeholder text is replaced like text. Office's own smart tags
  keep their names (`City`, `PersonName`, `ProductID`), and so does
  `urn:schemas:contacts`, the namespace Office's person name smart tag writes,
  which 0.5.2 to 0.8.1 replaced.
- **Settings.** Smart tag type names, namespaces and recognizer addresses, the
  schema library's namespace and locations, and the `w:saveThroughXslt`
  identifier are replaced.
- **Parts that are not well-formed XML** lose what a well-formed part loses,
  found by local names: VML hyperlink addresses, external relationship
  targets, VML shape ids and references, numbering formats, custom style ids
  and names, form field, building block and mail merge field names, data
  binding paths (a path that cannot be mapped is refused, as in a well-formed
  part) and schema references. A styles part with a `DOCTYPE` no longer stops
  the run.
- **The leak scan** reads all of these word by word, and also external
  addresses and the attributes replaced as text in any part (bookmark names,
  tooltips, document variables, form field and drawing names). Before, it
  looked there for two consecutive words of the text at most.

The [measurement](../../evidence/anonymize/README.md) was rerun: the same
summary as 0.8.1's, LibreOffice converting 207 of 209 sampled copies with the
same two not converted. Of 2,908 copies, ten differ from 0.8.1's: two lose a
document management system's smart tag names and a custom XML element name,
eight LibreOffice test documents whose parts paste several XML files together
lose custom style names, Word's default shape names and bullet level text.
Every finding is reproduced.

## Comment, note and story texts

- `FID004`–`FID006` and `FID010` read a paragraph boundary in a comment,
  footnote or endnote as a space; through 0.8.1 the paragraphs were joined
  with nothing between them. An edit that reflowed "First." and "Second."
  into one paragraph "First. Second." was reported as a lost comment or note
  (ERROR) although no word changed; it is not now. Joining "Confirm this" and
  "figure." into "Confirm thisfigure." joins two words and is reported now.
  `FID010` compares the tracked changes of a reflowed note it skipped before.
- `FID007` reads a text box's paragraphs in a header or footer once; through
  0.8.1 they were read twice, once glued to the paragraph holding the box.
- `fix` quotes a reply of several paragraphs the same way.

Which paragraph a word stands in is still reported, as `FID014` information.
Among 2,732 distinct DOCX in the repository and the public corpora, 23
comment and footnote bodies and 43 header and footer parts with text boxes
read differently; none is in the repository's evidence, whose records are
unchanged.

## Compatibility

- A reflowed comment or note no longer fails the default gate (exit 1 can
  become 0); two paragraphs joined without a space fail it now (exit 0 can
  become 1). A finding on a body of several paragraphs, or on a header or
  footer with a text box, carries another `body` and gets another baseline v2
  identity; review it and regenerate the baseline.
- `anonymize` copies of the affected documents differ from 0.8.1's with the
  same seed. A data binding path in a part that is not well-formed that cannot
  be mapped is refused (exit 2); the stricter leak scan can fail a run that
  0.8.1 passed (exit 1), and its `leaks` counts change.
- Other rule codes, severities, report fields, coverage schema 1, Doctor
  schema 1, SARIF 2.1.0 and CLI exits are those of 0.8.1. JSON/Doctor package
  version becomes `0.8.2`. See the [compatibility policy](../compatibility.md).
