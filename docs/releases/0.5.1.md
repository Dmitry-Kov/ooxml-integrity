# ooxml-integrity 0.5.1

Release candidate. `compare()` now reports a tracked replacement that deletes
and inserts again more unchanged words than it changes (`FID013`, WARN), which
leaves a reviewer looking at unchanged text struck through and added again.
Python 3.9+, dependencies and the MIT license are unchanged. The project
remains research-alpha.

## Tracked replacements wider than the change (`FID013`)

A tracked replacement is a deletion and an insertion side by side, by one
author. Word records the words that changed. In the review-history benchmark
docx-cli edited a footnote by deleting its whole text and inserting it again
with one phrase changed: nothing was lost and accepting gives the right text,
so no rule reported it, but a reviewer sees six unchanged words struck through
and added again under the editor's name.

- `FID013` (WARN) reads the replacements the edit added, in the main document,
  each effective header/footer slot and the footnote and endnote parts: a
  deletion and an insertion by one author that touch, neither of whose kind,
  author and effective date the source story had.
- It counts the whitespace-separated words the two texts share at their start
  and end, and reports a replacement when they are at least four and outnumber
  the words it changes. Words shared in the middle do not count, since a
  rewrite can reuse `the` and `of`. A replaced phrase that keeps a word or two
  of itself is below the threshold, and so is a real agent's sentence rewrite
  that keeps its first four words and changes nine.
- A person who selects a sentence and types it again with one word changed
  produces the same markup. A pipeline that deliberately replaces whole
  sentences can declare it with an
  [expectation](../configuration.md#changes-the-edit-was-asked-to-make).

Among the 1,051 labelled pairs this repository compares, `FID013` fires on the
four docx-cli note edits only and on no correct benchmark output. Reading the
review-history benchmark again, damaged outputs caught rise to 61 of 69 without
expectations, 65 with 0.4.8's and 67 when `FID012` is expected too; correct
outputs flagged stay at 130, 12 and 12.
[Scope](../review-edit-warnings.md#fid013-a-tracked-replacement-wider-than-the-change),
[analysis](../../evidence/review-history-benchmark/expectations/README.md#tracked-replacements-wider-than-the-change).

## Compatibility

`FID013` is a new WARN finding; it never fails the default gate. A
`--fail-on warn` gate comparing the output of a tool that rewrites whole
sentences or notes as tracked replacements now fails; declare it with an
expectation or turn it off with a reason. Its baseline v2 identity hashes the
story, author and both texts. Other rule codes, severities, messages, report
fields, coverage schema 1, Doctor schema 1, SARIF 2.1.0, CLI exits 0/1/2,
baseline v2 identities and the `anonymize` command are those of 0.5.0.
JSON/Doctor package version becomes `0.5.1`. See the
[compatibility policy](../compatibility.md).

## Validation and publication

[Candidate validation](../../evidence/releases/0.5.1/README.md) passed:
2217 tests with 7 documented skips, on Python 3.12 and 3.14, the 220-pair
producer corpus, 30 revision pairs and 168 stored editor output pairs, the
frozen checker replay, the four comment-story pairs, reference-deck assertions,
a rerun of the anonymize measurement with the same result, strict wheel/sdist
metadata checks and both fresh installations, plus all 7 real Chromium/Pyodide
scenarios against the exact local candidate wheel. The installed-package smoke
adds the 0.5.1 control: `FID013` on a sentence replaced to change one word and
not on a replaced phrase. No new Office, agent or model run was
part of release packaging. Local candidate and later publication hashes are
separate records.

After candidate checks pass, CI must pass on the exact merged main commit before
tagging. The Release workflow then verifies the remote pinned Action, rebuilds
and tests distributions, publishes those files to PyPI, and creates the GitHub
Release. Public PyPI installation/hash verification and consumer/demo pin updates
follow publication. See [release procedure](../releasing.md).

Use these pins **after publication**:

```sh
python -m pip install --upgrade ooxml-integrity==0.5.1
python -m ooxml_integrity --version
```
