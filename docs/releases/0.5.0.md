# ooxml-integrity 0.5.0

Published 2026-10-06T04:31:17Z on [PyPI](https://pypi.org/project/ooxml-integrity/0.5.0/)
and as a [GitHub Release](https://github.com/Dmitry-Kov/ooxml-integrity/releases/tag/v0.5.0). `ooxml-integrity anonymize`
writes copies of a document or a source/edited pair with the content replaced
and the structure kept, so a defect can be shared, and says whether the
checker's findings came back. The checks themselves are those of 0.4.9.
Python 3.9+, dependencies and the MIT license are unchanged. The project
remains research-alpha.

## Sharing a defect (`anonymize`)

A report about a lost comment or a misattributed revision is most useful with
the two files that show it, and they are usually confidential.

```sh
ooxml-integrity anonymize original.docx edited.docx -o share/
```

- Each word becomes a random word of the same length and character classes,
  the same in both files of a run, so comparisons keep their meaning. Words
  are read across runs and, in a paragraph with tracked changes, as it reads
  with the new changes rejected, which is what the comparison reads.
- Authors become `Author 1`, `Author 2`, ...; dates move by one random offset;
  document properties, external addresses, custom style and other names and
  custom XML are replaced. Pictures become 1x1 placeholders, embedded
  workbooks an empty workbook, other embedded objects empty parts.
- The checks then run on the originals and the copies. The report says
  whether every finding came back, by code, severity, part and location, and
  lists places still holding words of the original text, without the words.
  Exit `0` when every finding came back and nothing was left, `1` when the
  copies were written but not, `2` when the files cannot be read.
- `.docx` only; Strict Open XML is refused. A reader of the copies still
  learns the shape of the text: word lengths, capitals and digits, which
  words repeat, how many comments and revisions there are.

On every labelled pair in the repository (1,062) and on 1,848 public
documents, every finding came back and the leak scan reported nothing; 17
copies chosen for their content open in Word for Mac without an error or a
repair offer. [What is replaced and kept](../anonymize.md),
[measurement](../../evidence/anonymize/README.md).

## The GitHub Action

The Action now sets up Python with `actions/setup-python` v7 instead of v5.
Since v6 it runs on Node 24, so a self-hosted runner needs GitHub Actions
runner v2.327.1 or later; GitHub-hosted runners already have it. Its inputs
and outputs are unchanged.

## Compatibility

Rule codes, severities, messages, report fields, coverage schema 1, Doctor
schema 1, SARIF 2.1.0, CLI exits 0/1/2 and baseline v2 identities are those of
0.4.9: no finding changes. The minor version is for the new command.
`anonymize --json` has no schema version yet; its fields can change until a
release documents them, and its replacement words differ in every run.
JSON/Doctor package version becomes `0.5.0`. See the
[compatibility policy](../compatibility.md).
