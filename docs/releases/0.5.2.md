# ooxml-integrity 0.5.2

Release candidate. `anonymize` now replaces a firm's own schema names, which
copies made by 0.5.0 and 0.5.1 kept. The checks are those of 0.5.1. Python
3.9+, dependencies and the MIT license are unchanged. The project remains
research-alpha.

## Anonymized copies: a firm's own schemas

A security review found that a template's custom XML kept its namespace
(`http://schemas.<bank>/contracts`), the element names of its data
(`Contract`, `ClientName`) and the data binding path into them, while their
values were replaced. The leak scan did not see them, since none of those names
occurs in the text. If you shared a copy made by 0.5.0 or 0.5.1 of a document
with custom XML data, check its `customXml` parts.

- Namespace URIs outside the format's and Office's own are replaced, with the
  element and attribute names in them, the same way in the data, its
  properties part and data binding paths, so the bindings still resolve.
  Names in Office's namespaces, such as SharePoint's `properties`, are kept.
- Field instructions keep their field type and switches (`HYPERLINK`, `\h`,
  `\* MERGEFORMAT`) and lose their arguments. A made-up field type made
  LibreOffice refuse one copy.
- Numbering formats (`Article %1.`) lose their words and keep `%1`.
- The leak scan also reads part names and names in custom namespaces.

Every finding of the 1,062 labelled pairs and 1,848 public documents is still
reproduced on the copies, with no leak report; 75 public documents use custom
namespaces. [SECURITY.md](../../SECURITY.md#anonymized-copies) says what the
copies keep and how to report a leak privately;
[what is kept](../anonymize.md#what-is-kept),
[measurement](../../evidence/anonymize/README.md#a-firms-own-schemas-and-field-types).

## Compatibility

No finding changes: rule codes, severities, messages, report fields, coverage
schema 1, Doctor schema 1, SARIF 2.1.0, CLI exits 0/1/2 and baseline v2
identities are those of 0.5.1. `anonymize` writes different copies of a
document with custom XML, field instructions or worded numbering formats; its
JSON report has no schema version yet. JSON/Doctor package version becomes
`0.5.2`. See the [compatibility policy](../compatibility.md).

## Validation and publication

[Candidate validation](../../evidence/releases/0.5.2/README.md) passed:
2221 tests with 7 documented skips, on Python 3.12 and 3.14, the 220-pair
producer corpus, 30 revision pairs and 168 stored editor output pairs, the
frozen checker replay, the four comment-story pairs, reference-deck assertions,
a rerun of the anonymize measurement with the same result, strict wheel/sdist
metadata checks and both fresh installations, plus all 7 real Chromium/Pyodide
scenarios against the exact local candidate wheel. The installed-package smoke
adds the 0.5.2 control: a firm's custom XML schema anonymized with its binding
kept. No new Office, agent or model run was
part of release packaging. Local candidate and later publication hashes are
separate records.

After candidate checks pass, CI must pass on the exact merged main commit before
tagging. The Release workflow then verifies the remote pinned Action, rebuilds
and tests distributions, publishes those files to PyPI, and creates the GitHub
Release. Public PyPI installation/hash verification and consumer/demo pin updates
follow publication. See [release procedure](../releasing.md).

Use these pins **after publication**:

```sh
python -m pip install --upgrade ooxml-integrity==0.5.2
python -m ooxml_integrity --version
```

```yaml
- uses: Dmitry-Kov/ooxml-integrity@v0.5.2

```
