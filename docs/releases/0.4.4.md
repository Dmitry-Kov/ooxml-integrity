# ooxml-integrity 0.4.4

Published 2026-09-25T13:27:22Z on [PyPI](https://pypi.org/project/ooxml-integrity/0.4.4/)
and as a [GitHub Release](https://github.com/Dmitry-Kov/ooxml-integrity/releases/tag/v0.4.4).
This patch corrects false positives found on public real-world documents and
checked in Word and PowerPoint, and reports Strict Open XML as not checked.
Python 3.9+, dependencies and the MIT license are unchanged. The project
remains research-alpha.

## Gate changes and limits

On six [public test corpora](../real-world-corpora.md) (1,887 DOCX, 605 PPTX),
DOCX with an ERROR fall from 283 in 0.4.3 to 130, Word-saved ones from 150 to
80 of 1,522, and ERROR findings from 498 to 203. Many remaining errors describe
real damage in bug reproductions.

These corrections remove false errors or warnings and can change exit 1 to 0:

- `FTN002` recognises separator and continuation-separator notes by `w:type`;
  LibreOffice and Word 2007 write their ids as `0`/`1`.
- `NUM001`/`NUM002` treat `numId="0"` as removing numbering. `NUM004` follows
  `w:numStyleLink` and accepts levels defined in `w:lvlOverride/w:lvl`.
- `PKG005` no longer reports `[Content_Types].xml` itself.
- `TBL002` counts `w:gridBefore`/`w:gridAfter` columns and cells inside
  `w:sdt`/`w:customXml` (306 warnings on the corpora became 32).
- `PKG004` is a WARN when every relationship part is declared by `Override`
  instead of a `.rels` default.
- `XML001` is a WARN for a malformed part that no relationship reaches. Related
  parts, and packages with an unreadable relationship part, keep the ERROR.
- `CMT001`–`CMT005` read comment ranges and references in the header, footer,
  footnote and endnote parts that the main part relates, so a comment anchored
  only there is not orphaned. [Labelled pairs](../../evidence/docx-comment-stories/README.md).
- The main document part is the target of the package `officeDocument`
  relationship, not the name `word/document.xml`. Word Online's
  `word/document22.xml` and similar packages are now checked, and `compare()`
  no longer raises `KeyError` for them.

These report more and can change exit 0 to 1:

- New `PKG009` ERROR for Strict Open XML DOCX and PPTX: their checks were not
  run. The 17 Strict DOCX in the corpora, all saved by Word, passed with only
  `REL003` INFO; Strict PPTX were called unreadable (`PKG002`). Projects that
  accept Strict files unchecked can set `[severity] PKG009 = "warn"`.
- `REL001` for `officeDocument` relationships to more than one part; `PKG006`
  when the related main part is missing, even beside an unrelated
  `word/document.xml`, or has a root other than `w:document`.
- `CMT001`–`CMT004` findings in header, footer and note parts.

`PKG005` keeps its ERROR and now says that Word asks to recover the document.
`PKG002` keeps rejecting bytes after the ZIP end record and now counts them.

Word for Mac 16.113 and PowerPoint for Mac 16.113.2 were checked on these
cases; the [observations](../real-world-corpora.md#checked-in-word-and-powerpoint)
include an unreferenced `[trash]/` item and a single trailing newline, both of
which made Office offer a repair. Windows behavior was not tested. Styles,
numbering, footnote and endnote parts are still read under their conventional
names, and the source comparison does not count comment anchors in notes.

## Compatibility

`PKG009` is a new rule code; no code is removed or repurposed. Other retained
severities are unchanged, except `XML001` for parts no relationship reaches.
Report fields, coverage schema 1, Doctor schema 1, SARIF 2.1.0, CLI exits 0/1/2
and baseline v2 identities are unchanged, and findings in `word/document.xml`
keep their parts. Findings in a renamed main part or in a header, footer or note
part name that part. Messages are excluded from baseline fingerprints. For a
missing main part and for Strict input, `compare()` raises `ValueError` instead
of `KeyError` or an empty comparison; the CLI reports `FID000`. JSON/Doctor
package version becomes `0.4.4`. See the [compatibility policy](../compatibility.md).
