# ooxml-integrity 0.8.4

Published 2026-10-25T07:56:17Z on [PyPI](https://pypi.org/project/ooxml-integrity/0.8.4/)
and as a [GitHub Release](https://github.com/Dmitry-Kov/ooxml-integrity/releases/tag/v0.8.4). A new ERROR rule,
`PKG012`, reports an `Override` whose part name has an escape Word refuses; an
`Override` covers its part whatever the letter case; text in a `.pptx` box no
taller than its insets is reported; and a shape some of whose text has no font
metrics gets `PPT000`. Python 3.9+, dependencies and the MIT license are
unchanged. The project remains research-alpha.

## Content types

- **`PKG012` (ERROR): an `Override` with an escape Word does not accept.** Its
  `PartName` escapes an unreserved character (`%6E` for `n`), a slash, a
  backslash or a non-ASCII character, or has a `%` that starts no escape. Word
  for Mac refused all eight such variants of a Word-saved document, also those
  whose `Override` names a part the package lacks, and opened the three that
  escape a space, `%` or `#` ([Word check](../../evidence/docx-escaped-part-names/README.md)).
  No rule reported it before.
- **An `Override` covers its part in any letters.** `PKG005` and `PKG010`
  compared part names exactly, so without an `xml` `Default` an `Override` for
  `/WORD/COMMENTS.XML` left `word/comments.xml` "not covered" (`PKG005`
  ERROR), a file Word opens, and a wrong type on such an `Override` was
  `PKG005` instead of `PKG010`, which `fix` repairs. Names are compared
  without regard to case and not unescaped
  ([Word check](../../evidence/docx-case-overrides/README.md)).

Neither change fires on the 1,903 public Word files of the real-world corpora.

## `.pptx`

- **A box no taller than its insets.** It leaves no room for text, and through
  0.8.3 text in it was never reported, while a box 0.8pt taller was. Text
  taller than the shape is `PPT001` ERROR; text no taller than the shape is a
  WARN, because OOXML moves insets that meet and where such text is drawn
  depends on the renderer ([thin boxes](../pptx-thin-boxes.md)). LibreOffice
  drew the text of every probe box without room outside it. Of 605 public
  decks, LibreOffice's `tdf165732` gains 2 ERROR and its three
  `TextDistancesInsets` decks 70 WARN.
- **Text without font metrics.** A run whose font could not be read was left
  out of the layout while the shape counted as measured, so a fit verdict on
  the rest passed silently. The shape now gets `PPT000` ERROR naming the fonts
  left out, and its fit is still checked on the rest. No public deck changes.

## Compatibility

- `PKG012` is a new ERROR finding of `check()`, so a document that passed the
  default gate can exit 1. It belongs to `package.content-types`; its baseline
  identity is file, code and the `Override`'s location.
- A part an `Override` names in other letters is no longer `PKG005` (exit 1
  can become 0), and a wrong type on such an `Override` is `PKG010` instead of
  `PKG005`.
- A `.pptx` box no taller than its insets gets `PPT001` (a deck that passed
  can exit 1). A shape with text left unmeasured gets `PPT000` ERROR, and its
  coverage items `pptx.font-metrics` and `pptx.text-overflow` are `skipped`.
- Other rule codes, severities, report fields, coverage schema 1, Doctor schema
  1, SARIF 2.1.0 and CLI exits are those of 0.8.3. JSON/Doctor package version
  becomes `0.8.4`. See the [compatibility policy](../compatibility.md).
