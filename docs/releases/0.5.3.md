# ooxml-integrity 0.5.3

Published 2026-10-09T17:34:39Z on [PyPI](https://pypi.org/project/ooxml-integrity/0.5.3/)
and as a [GitHub Release](https://github.com/Dmitry-Kov/ooxml-integrity/releases/tag/v0.5.3). The source distribution's
test suite passes, which 0.5.2's did not. The checks are those of 0.5.2.
Python 3.9+, dependencies and the MIT license are unchanged. The project
remains research-alpha.

## The source distribution's tests

A packager who builds from the sdist and runs its tests got failures: from the
published 0.5.2 sdist, 13 failed and 16 errors. Its include list matched
`demo/README.md` and `runs/README.md` as well as the top-level README, so the
unpacked sdist had `demo/` and `runs/` with only their READMEs in them. The
tests that skip when the demo is absent ran and failed, and the agent run
fixtures were missing.

- The include list is anchored at the root. `runs/`, `action.yml` and
  `.github/` are shipped; the demo is not.
- The demo, browser-preview and results-page tests skip on the files they read.
- CI builds the sdist, unpacks it and runs the suite from it, and so did the
  candidate validation below.

## Documentation and the results page

- The README's opening names no version. It named the release the demo pinned,
  which changes only after publication, so the PyPI page of 0.5.2 announced
  0.5.1.
- The README states the six controlled defect cases precisely: five are found
  by checking the edited file alone, a Markdown round trip only by comparing
  it with its source.
- [`--expect`](../configuration.md#changes-the-edit-was-asked-to-make) lists
  the `extra` keys and values each fidelity finding carries, `FID001` to
  `FID013`.
- The [results page](https://dmitry-kov.github.io/ooxml-integrity/benchmark/)
  states what 0.4.8 and 0.4.9 did from the expectations analysis run with those
  published wheels, where it recounted this checkout's run without later
  rules. Every attempt gives the same codes in every reading, so the numbers
  stay ([analysis](../../evidence/review-history-benchmark/expectations/README.md#published-versions)).

## Compatibility

No finding changes: rule codes, severities, messages, report fields, coverage
schema 1, Doctor schema 1, SARIF 2.1.0, CLI exits 0/1/2, baseline v2
identities and `anonymize` output are those of 0.5.2. The wheel's code changes
only in the version. The sdist gains the agent run fixtures in `runs/`,
`action.yml` and `.github/`, and loses `demo/`, which held only READMEs.
JSON/Doctor package version becomes `0.5.3`. See the
[compatibility policy](../compatibility.md).

## Validation and publication

[Candidate validation](../../evidence/releases/0.5.3/README.md) passed:
2222 tests with 7 documented skips, on Python 3.12 and 3.14, the
suite run from the unpacked sdist (2195 passed, 34 skipped), the 220-pair
producer corpus, 30 revision pairs and 168 stored editor output pairs, the
frozen checker replay, the four comment-story pairs, reference-deck assertions,
a rerun of the anonymize measurement with the same result, strict wheel/sdist
metadata checks and both fresh installations, plus all 7 real Chromium/Pyodide
scenarios against the exact local candidate wheel. No new Office, agent or
model run was part of release packaging. Local candidate and later
publication hashes are separate records.

All source CI jobs passed on exact main commit `ebe727972e02eb206b70ce2ae163517b4c08f5ef` before
annotated tag `v0.5.3` was pushed. The [Release workflow](https://github.com/Dmitry-Kov/ooxml-integrity/actions/runs/37966787846)
verified the public Action ref, rebuilt and tested both distributions plus the
exact wheel in Pyodide, published to PyPI, and created the GitHub Release.
[Publication receipt](../../evidence/releases/0.5.3/publication.json) records
source CI, tag identity, assets and fresh public PyPI installation.
