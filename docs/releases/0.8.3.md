# ooxml-integrity 0.8.3

Release candidate. Empty paragraphs and empty lines in `.pptx` text boxes take
their height, and the anchor decides whether blank rows above or below the
text show; two new ERROR rules report a content type or a relationship `Id`
declared twice, which Word refuses; and a config, baseline or report path that
cannot be used is a usage error (exit 2) instead of a traceback. Python 3.9+,
dependencies and the MIT license are unchanged. The project remains
research-alpha.

## `.pptx`: empty paragraphs and empty lines

- **An empty line is as tall as the mark that ends it:** the paragraph's
  `a:endParaRPr` (inherited like a run's size when absent) or the break's run
  properties. Through 0.8.2 an empty paragraph added no height, so text pushed
  out of its box by empty paragraphs between bullets was reported as fitting,
  and an empty line between breaks or after a trailing break was always 18pt.
- **Spacing.** An empty paragraph keeps its space before and after. There is no
  space below the last paragraph, as there was none above the first.
- **The anchor.** Blank rows above the first line of text count for
  top-anchored text, those below the last for bottom-anchored text, and their
  difference for centred text. A top-anchored title followed by a few breaks is
  no longer reported as overflowing when nothing is drawn outside it. A
  placeholder without an anchor takes its layout placeholder's (the one with
  its `idx`, else the first of its type), then the master's.

PowerPoint for Mac 16.114.1 and LibreOffice 25.8.4.2 drew the new
[fixture](../pptx-empty-lines.md) as the model predicts in all 18 anchor
verdicts, and in 12 heights within 1pt and 0.05pt. Of 605 public decks, 8
change: 14 `PPT001` and 2 `PPT002` go, 8 `PPT001` and 1 `PPT002` come.

## A content type or relationship `Id` declared twice

- **`PKG011` (ERROR):** a second `Default` for an extension or `Override` for
  a part name in `[Content_Types].xml`, compared as OPC compares them (letters
  without regard to case, a part name also unescaped).
- **`REL004` (ERROR):** one `Id` on two relationships of the same relationship
  part.

A script that adds a comments part or a relationship without reading what the
package already declares writes these. Word for Mac refused all eight
single-change variants of a Word-saved document, also those whose second
declaration repeats the first ([Word check](../../evidence/docx-opc-duplicates/README.md));
0.8.2 reported nothing on six of them. Neither rule fires on the 1,903 public
Word files of the real-world corpora.

## Usage errors

A config that is not valid TOML or not UTF-8, a directory given as a config or
baseline, a `severity` that is not a table, `ignore` or `expect` that are not
arrays of tables, a `[tool.ooxml-integrity]` that is not a table, a baseline
that is not JSON or whose findings are not counts, and a `--write-baseline` or
`--sarif` path that cannot be written raised a traceback and exited 1, the code
for findings. `check` and `mcp` now name the file and the problem and exit 2.

## Compatibility

- `PPT001` and `PPT002` change on decks with empty paragraphs or empty lines: a
  deck that passed can exit 1, and one that failed can exit 0. Their messages
  carry other heights and line counts there. Codes, severities and baseline v2
  identities are unchanged.
- `PKG011` and `REL004` are new ERROR findings, so a document that passed the
  default gate can exit 1. They belong to the existing coverage items
  `package.content-types` and `package.relationships`; their baseline identity
  is file, code and the location of the second declaration.
- An unusable config, baseline or report path exits 2 where it exited 1. A
  baseline count must be a whole number of at least 0: `--write-baseline` never
  wrote another, but a count edited into a string such as `"2"` was read
  before.
- Other rule codes, severities, report fields, coverage schema 1, Doctor schema
  1 and SARIF 2.1.0 are those of 0.8.2. JSON/Doctor package version becomes
  `0.8.3`. See the [compatibility policy](../compatibility.md).

## Validation and publication

[Candidate validation](../../evidence/releases/0.8.3/README.md) passed:
2742 tests with 7 documented skips, on Python 3.12 and 3.14, the
suite run from the unpacked sdist (2714 passed, 35 skipped), the 220-pair
producer corpus, 30 revision pairs and 168 stored editor output pairs, the
frozen checker replay, the four comment-story pairs, reference-deck assertions,
a rerun of the anonymize measurement with the same result, strict wheel/sdist
metadata checks and both fresh installations, plus all 7 real Chromium/Pyodide
scenarios against the exact local candidate wheel. The installed-package smoke
adds the 0.8.3 controls: `PKG011` on a repeated `Override`, `REL004` on a
repeated relationship `Id`, exit 2 for a config that is not TOML, and empty
`.pptx` paragraphs as tall as their marks. No new
Office, agent or model run was part of release packaging. Local candidate and later
publication hashes are separate records.

After candidate checks pass, CI must pass on the exact merged main commit before
tagging. The Release workflow then verifies the remote pinned Action, rebuilds
and tests distributions, publishes those files to PyPI, and creates the GitHub
Release. Public PyPI installation/hash verification and consumer/demo pin updates
follow publication. See [release procedure](../releasing.md).

Use these pins **after publication**:

```sh
python -m pip install --upgrade ooxml-integrity==0.8.3
python -m ooxml_integrity --version
```
