# Review-history benchmark sources

Sources for the planned review-history benchmark: when a tool makes an ordinary
edit to a DOCX that already carries comments, other authors' pending revisions
and notes, what survives. The benchmark protocol, tasks and oracle are not yet
declared; this directory only fixes its inputs.

- **S1** is the existing [corpus/base.docx](../../../corpus/base.docx).
- **S2** is a review record written by Word for Mac, below.

## S2: a Word-written review record

[review-base.docx](review-base.docx) is generated by
`python research/review_history_sources.py build` and has no review markup: a
short services agreement with a numbered list, a table, a footnote, an endnote,
a header and footer, a content control and a hyperlink. Word for Mac then wrote
the review record by following [s2-word-checklist.md](s2-word-checklist.md).
The base, the checklist, the audit script and eleven requirements were pinned in
[s2-declaration.json](s2-declaration.json) at 2026-09-29T09:19:48Z, before Word
opened the file.

`word-review.docx` has, all written by Word 16.113.2 (26092012), Office LTSC
Standard for Mac 2024:

- a comment thread (Reviewer A on `Completion Date`, Reviewer B's reply linked
  through `w15:paraIdParent`) and a resolved comment in a table cell
  (`w15:done="1"`), with `commentsIds`, `commentsExtensible` and `people.xml`;
- Reviewer A's replacement and inserted sentence, and Reviewer B's deletion
  nested inside that insertion;
- a moved list item (`moveFrom`/`moveTo` with named move ranges);
- Reviewer B's run (`rPrChange`, bold) and paragraph (`pPrChange`, justify)
  formatting changes;
- Reviewer A's revision in the default header and Reviewer B's in the endnote.

The [capture record](s2-capture.json) keeps hashes, prompts and every deviation
from the checklist. The main one: an agent drove Word's own UI through macOS
accessibility, where the checklist assumed a person. Word showed classic comment
UI; a first resolve attempt from the context menu did not take and the Review
menu command did; a stray insertion in a heading was undone before the next
step. The operator's original notes (Russian) and read-only verification are
kept as [s2-operator-notes.ru.md](s2-operator-notes.ru.md) and
[s2-operator-verification.json](s2-operator-verification.json).

The declared audit script ran unchanged: `word-review.docx` meets all eleven
requirements, including the privacy one (no e-mail, presence identity, label,
company or unexpected author). Rejecting every revision in either output gives
the base text in the body, header, footer and both note parts; accepting every
revision gives only the checklist's edits. `tests/test_review_history_sources.py`
re-checks all of this, and tests the audit itself on a simulated package with
one seeded removal per requirement.

## Checker observation

`ooxml-integrity` 0.4.5 `check()` is clean on both outputs. `compare()` from the
base to `word-review.docx` reports two errors on this intended, fully tracked
review:

- `FID006` says the endnote is gone and its text "is not there under any id".
  The endnote keeps its id; `1` is a tracked deletion and `15` a tracked
  insertion. Note and comment bodies are matched on `w:t` text only.
- `FID007` says the default header is "missing or changed". It changed through
  a tracked replacement; the old `3` is kept as `w:delText`.

This is recorded as observed, not corrected here. Any tool that correctly
tracks an edit in a note body or header will get the same errors, so the
benchmark's note and header tasks cannot yet separate a correct edit from a loss.
