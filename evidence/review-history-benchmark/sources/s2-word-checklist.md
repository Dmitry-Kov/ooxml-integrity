# S2 Word for Mac checklist — declared before Word runs

`review-base.docx` is generated by `research/review_history_sources.py build`
and has no review markup. A person follows the steps below in Word for Mac, so
every comment, thread, revision and person record in the result is written by
Word through its normal UI. No script edits the document before or after Word.
The base, this checklist and the audit script are pinned in
[s2-declaration.json](s2-declaration.json) before the first step.

Work on a copy of the base in a local folder that is not synced to a cloud
service. Keep ordinary alerts on. Do not use Accept, Reject or repair. Record
the Word version and every prompt or deviation.

## Before opening the document

1. Word > About Word: note the version and build.
2. Word > Settings > User Information: note the current name and initials so
   they can be restored at the end. Set first name `Reviewer`, last name `A`,
   initials `RA`. If an option to always use these values regardless of the
   Office sign-in is shown, turn it on.
3. Word > Settings > Security & Privacy: "Remove personal information from this
   file on save" stays off; it would replace both reviewer names with "Author".

## Reviewer A

4. Open `review-base.docx`. On the Review tab, Track Changes is on (the file
   enables it) and the markup view shows all markup.
5. Section 1: select exactly `Completion Date`, add a new comment
   `Completion Date is not defined.` and post it. The card must show
   `Reviewer A`; if it shows another name, stop.
6. Fee table, Discovery row: select `EUR 12,000`, add a new comment
   `Check this against the approved budget.` and post it.
7. Section 4: double-click `thirty` and type `forty-five`.
8. Same paragraph: click after `invoice.`, type a space and
   `The Client may withhold any disputed amount.`
9. Section 2: triple-click item (c) `Comply with the Client's information
   security policy.` to select the whole item, press Cmd+X, click at the start of
   item (a) `Attend a monthly steering meeting…` and press Cmd+V. A tracked move
   shows green double strikethrough at the old place and green double underline
   at the new one. If the old place shows an ordinary red deletion instead, undo
   until the item is back, drag the selected item to the start of item (a), and
   record that cut and paste did not produce a move.
10. Header: double-click the header, select `3` in `Draft 3` and type `4`.
    Double-click the body to leave the header.
11. File > Save As: same folder, name `review-a.docx`, format Word Document
    (.docx). Close the document.

## Reviewer B

12. Word > Settings > User Information: last name `B`, initials `RB`.
13. Open `review-a.docx`.
14. On the comment `Completion Date is not defined.`, reply
    `Agreed. Add it to Schedule 1.` and post it. The reply must show
    `Reviewer B`; if it shows another name, stop.
15. On the comment `Check this against the approved budget.`, open the thread
    menu and choose Resolve thread.
16. Section 4: in the sentence Reviewer A inserted, double-click `any` and press
    Delete.
17. Section 5: select `gross negligence` and press Cmd+B.
18. Section 6: click anywhere in `Either party may terminate…` and press Cmd+J
    (Justify).
19. The endnote at the end of the document: select `1` in `1 September 2026`
    and type `15`.
20. File > Save As: same folder, name `word-review.docx`, format Word Document
    (.docx). Close the document.
21. Restore the User Information values noted in step 2.

## Recorded afterwards

Word version and build; each prompt or dialog and the choice made; whether step
9 recorded a move on the first attempt; any other deviation. The audit
(`python research/review_history_sources.py audit word-review.docx`) is then run
against the requirements declared in s2-declaration.json. A failed requirement
is reported as observed, not fixed by editing the file.
